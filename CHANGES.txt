Sarah Haas portfolio — full implementation, approved editorial redesign
Prepared: 2026-07-28
Branch this reflects: claude/sarahehaas-github-io-connection-s14zfb

This ZIP is the complete, current file state of the site — every page,
across all three implementation passes. It supersedes any earlier ZIP or
CHANGES.txt from this project.

VISUAL SYSTEM
-------------
Implements the approved design-direction spec exactly: warm butter
background (#f2ede4), Newsreader serif headlines + Public Sans body/UI
type (loaded via Google Fonts), teal accent (#0a6b74) used for labels,
links, active states, and stat emphasis, hairline dividers, 6-8px
rounded corners on cards/buttons, no dark inverted bands (max two
background colors anywhere: butter and a light teal tint).

PAGE STRUCTURE
--------------
- Home / Portfolio: featured case studies are editorial-list rows
  (hairline-separated, no card boxes), not the earlier bordered grid.
- Case studies (all 5): shared template with a Problem -> Outcome
  one-line opener under the hero, a sticky left-rail table of contents
  (Challenge/Approach/Impact/Reflection, active-section highlight on
  scroll, reveals at >=1180px viewport width so it never overlaps the
  reading column), tinted stat panels, white bordered diagram/artifact
  cards, and Role/Scope/Contribution hairline cards.
- About: portrait + intro, 5-step "My approach" grid, "Beyond the work"
  now uses the same bordered-card treatment as case-study involvement
  cards.
- Contact: rebuilt to a single bordered card — Email, LinkedIn, and a
  Resume row. The Resume row links to resume.pdf, which does not exist
  in this repo yet; this is intentional, per direct instruction, as a
  placeholder for when a real resume file is supplied. It will 404 until
  that file is added.

PASSWORD / ROUTING (UNCHANGED BEHAVIOR)
----------------------------------------
- One shared localStorage unlock (sarahPortfolioUnlockedUntil), valid
  8 hours, shared across Portfolio and all 5 case studies.
- No redirects, no query parameters, anywhere in the flow.
- Direct links to a protected page show the in-page overlay only when
  no valid unlock exists; otherwise the page is immediately visible.
- script.js's gate logic itself was not modified in this pass beyond
  Phase 1's original localStorage/8-hour-expiry rewrite; this pass only
  appended two new, independent, self-contained behaviors after it: a
  nav scroll-shadow effect and the case-study TOC's scroll-spy /
  click-to-scroll behavior. Neither touches the password logic.

KNOWN, INTENTIONAL EXCEPTIONS
------------------------------
- resume.pdf does not exist yet (see above) - the link is a deliberate
  placeholder, not a bug.
- Text colored #a89e8f (contact-row labels, inactive TOC items, figure
  captions) sits below the 4.5:1 AA-normal contrast ratio against the
  butter background (it measures ~2.3:1). This was reviewed and
  accepted as-is: these are captions/secondary labels, not primary
  reading text, and are either large enough for the AA-large 3:1
  threshold or explicitly decorative/secondary. All primary body copy
  and link text on the site clears 4.5:1 (verified - see below).
- advertiser-education.html and device-help.html remain unfinished
  placeholder pages, intentionally not linked from navigation, the
  homepage, or the Portfolio grid.
- portfolio.html, autofill-optimization.html, in-app-browser.html remain
  as redirect stubs so old bookmarked links keep working.
- device-help.html has two instances of an unescaped "AT&T" and
  advertiser-education.html has one unescaped "&" in its H1 (should be
  "&amp;"); both are pre-existing, cosmetic-only (browsers render them
  correctly as-is), and out of scope since neither page's content was
  part of this redesign pass.

VERIFICATION PERFORMED BEFORE PACKAGING
----------------------------------------
1. HTML validity: every .html file run through HTML Tidy in
   errors-only mode. Zero errors across all 14 files.
2. Asset/link/fragment check: every local src/href and every #anchor
   link resolves to a real file or id in this ZIP, with the one
   intentional exception (resume.pdf) noted above.
3. Live local-link crawl: served the site locally and requested every
   internal link and asset; all returned HTTP 200 except the
   intentional resume.pdf placeholder (404, expected).
4. Password-flow tests: fresh lock, wrong-password error, correct
   unlock with no query string added to the URL, shared unlock
   verified across all 8 protected pages without re-prompting, and
   8-hour expiry confirmed by forcing the stored timestamp into the
   past and reloading. All pass.
5. Console errors: zero on any of the 11 rendered pages.
6. Responsive: scripted scrollWidth vs. clientWidth check at a 390px
   mobile viewport confirms zero horizontal scroll on any page.
7. Keyboard/accessibility: Tab-focus produces a visible
   2px solid #0a6b74 outline as specified; heading levels (h1->h2->h3,
   no skipped levels) verified sequential on every page; WCAG contrast
   ratios computed for every text/background color pair in the system
   - all primary body text and link/accent text clears AA 4.5:1 (teal
   on butter measures 5.35:1); the one accepted exception is noted
   above.
8. Dead-code sweep: removed two leftover CSS rules with no matching
   HTML anywhere in the site (capability-card-wide, an unused .display
   utility hook).
