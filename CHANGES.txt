SCOPE
-----
Per approved plan, this pass touches only: the shared CSS design system,
shared password behavior, global navigation/footer, and the Autofill
Strategic Audit case study (as the representative page). All other pages
are content-unchanged; a few of them get one small markup fix described
below because it's shared chrome, not page content.

WHAT CHANGED

1. styles.css — full rewrite
   - Removed the "EDITORIAL MONOCHROME REFRESH" block that had been
     silently overriding the site to a white/gray palette and forcing
     filter:grayscale(1) on every case-study image. That block contained
     a second, conflicting :root declaration that was overriding the
     original warm color tokens.
   - Restored the warm cream background / near-black ink / deep-teal
     accent system as canonical, per your direction: teal used only for
     buttons, active nav/link states, thin rules, and stat emphasis.
   - Kept rectangular borders and no drop shadows throughout (no rounded
     cards).
   - Consolidated the stylesheet: removed roughly 1,500 lines of dead CSS
     left over from at least three earlier redesign passes (a pre-"cs-*"
     case-study system, a "Simplified Autofill case study" system, and
     assorted unused card/grid/timeline components). Every remaining
     selector was confirmed to be referenced by at least one current HTML
     file before being kept.
   - Added missing base rules for a few classes that were already in use
     in HTML but had no real CSS behind them (.page-hero, .lede,
     .case-layout, .stat/.stat-grid, .placeholder-shot) so Contact and the
     two orphaned placeholder pages don't regress.

2. script.js — password gate rewritten
   - Shared unlock moved from sessionStorage to a single localStorage
     value with an 8-hour expiration, so one password entry stays valid
     across Portfolio and all five case studies for 8 hours, including
     across new tabs/browser restarts within that window.
   - Removed the dead createOverlay() fallback function and the unused
     portfolio-filter button wiring (data-filter/data-category), neither
     of which is referenced by any current page.
   - No redirects, no query parameters, at any point in the flow.

3. Bug found and fixed: script tag ordering
   - Every protected page loads <script src="script.js"> BEFORE the
     .password-overlay <div> appears in the HTML. Without deferring
     execution, the gate script would run before the overlay exists in
     the DOM. The old script.js masked this with its createOverlay()
     fallback (building a duplicate overlay on the fly); removing that
     dead code exposed the bug. Fixed by adding the `defer` attribute to
     the script tag on every page that loads script.js, so it always runs
     after the full document (including the overlay) has parsed.
   - Files touched for this alone (one-line attribute change, no content
     changes): about.html, accessibility.html, advertiser-education.html,
     ai-workflows.html, autofill-audit.html, autofill.html, contact.html,
     device-help.html, hxp.html, index.html, work.html.

4. Cleanup (approved in prior review round)
   - Deleted: Sarah_Haas_Portfolio_PASSWORD_LOOP_FIX.zip,
     UPLOAD-INSTRUCTIONS.txt, BUILD-VERSION.txt.
   - Deleted 16 root-level images that were byte-for-byte duplicates of
     files already under assets/case-studies/ (verified via SHA-256
     before deletion).
   - Deleted image-4.png and image-8.png: generic "replace with real
     Figma export" wireframe placeholders, unreferenced by any page and
     already superseded by the real annotated assets in
     assets/case-studies/.
   - README.md rewritten to describe the current static-site project and
     give local-preview instructions, replacing the old manual
     zip-upload instructions for a workflow that's no longer in use.

VERIFICATION PERFORMED BEFORE PACKAGING
----------------------------------------
1. HTML validity: every .html file run through HTML Tidy in
   errors-only mode. Result: zero errors on all 14 files.
   Non-blocking notes: Tidy's HTML5 profile flags aria-current and
   aria-modal as "proprietary attributes" — both are standard, valid ARIA
