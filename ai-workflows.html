Redesigning how UX content moves into code

I designed and piloted an AI-assisted workflow that enabled content designers to add strings directly to the codebase and submit the actual string diffs for engineering review. Engineers retained ownership of the feature container, technical architecture, UI wiring, review, and final integration.

Challenge

The handoff separated content authority from content implementation.

Content designers authored the language, then engineers manually re-entered it in code. That translation step created wrong text, escaping errors, duplicate strings, incorrect descriptions, hash mismatches that could break translations, and repeated correction cycles.

Approach

Redesign the ownership boundary—not replace engineering.

Engineering built the feature container. I used the workflow to place the approved strings inside the relevant code files, validate them, and submit strings-only diffs. Engineering reviewed those diffs and integrated them with the broader feature implementation in separate code changes.

01

Content stays authoritative

The person responsible for the UX language also controls the exact text and descriptions that enter code.

02

Engineering stays authoritative

Engineers review conventions and hashes, wire strings into the UI, and own the surrounding architecture and integration.

03

AI bridges formatting

The skill handles repetitive platform syntax while confirmation tables, source-of-truth checks, diffs, and human review preserve quality.

Impact 1

Moved quality upstream

In the comparison workflow, the old process required eight correction diffs, abandoned three diffs, triggered more than 20 review warnings, and landed iOS hash mismatches. The pilot produced no correction diffs, abandoned diffs, warnings, or landed hash mismatches. Small issues were caught during the initial review round instead of after landing.

Impact 2

Created a scalable operating model

The work became more than a one-off prompt. I documented the workflow, published an internal skill, created review guidance, demonstrated the process, and captured engineering feedback on what would make it reusable across teams.

Before

Content Design wrote strings. Engineering retyped, formatted, validated, corrected, and wired them into the feature.

After

Content Design authored and submitted the actual string diffs. Engineering reviewed and integrated them into the feature code.

Reflection

AI created value by reducing translation loss between disciplines.

The strongest outcome was not “AI wrote code.” It was a cleaner collaboration model: Content Design took responsibility for the content layer in code, automation handled repetitive formatting, and Engineering focused on review, architecture, and integration.
