Designing an AI-assisted production workflow for UX strings

A human-in-the-loop workflow that enabled content designers to author, validate, and submit the actual string diffs in code while preserving engineering review and integration ownership.

Role, scope & contribution

My role

Workflow designer, pilot lead, content-design implementer, skill author, and partner to engineering.

Ownership model

Engineering built the feature container and surrounding implementation. Content Design owned the UX language and its string changes in code. Engineering reviewed and integrated those diffs into the broader product implementation.

Challenge

Manual handoff introduced translation loss between content and engineering.

Content designers finalized language, then engineers manually recreated it in code. That added implementation time and created avoidable correction diffs, abandoned diffs, warnings, hash mismatches, and post-land cleanup.

Approach

Move content ownership into the code workflow without removing engineering oversight.

EngineeringBuilds feature container and implementation→Content Design + AIAuthors, validates, and submits string diff in code→EngineeringReviews and integrates the diff

The AI assisted with structure, validation, source-of-truth checks, and repeatable implementation steps. The content designer still reviewed every change and owned the submitted diff.

Impact 1

Quality moved upstream.

In the comparison workflow, the manual process produced eight correction diffs, three abandoned diffs, more than 20 Phabricator warnings, and iOS hash mismatches in 88% of strings. The AI-assisted workflow produced none of those errors.

Impact 2

The pilot became a reusable team capability.

I documented the workflow, published an internal skill, created a quick-start process, demonstrated the approach, and established clear human and engineering review boundaries so others could use it safely.

Evidence & examples

Reflection

AI created value by strengthening ownership, not replacing expertise.

The durable innovation was not the prompt. It was a better division of labor: Content Design could own its implementation layer in code, while Engineering retained technical architecture, review, and integration.
